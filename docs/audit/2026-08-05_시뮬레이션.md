# 2026-08-05 상황 시뮬레이션 감사

## 왜 방식을 바꿨나

전날 감사(2026-08-04)는 멀티에이전트가 코드를 읽고 지적하는 방식이었다.
**66건 중 46건(70%)이 기각**됐다. 원인은 리뷰어의 성실함이 아니라 방법이다 —
코드를 읽어서 나온 의심은 대부분 틀린다. 남은 20건을 걸러내는 데 든 비용이,
얻은 13건의 가치를 거의 상쇄했다.

이번에는 **1차 심판을 실행 결과로 바꿨다.**

```
상황을 YAML로 진술  →  엔진 전 구간 실행  →  불변식 14종이 기계적으로 판정
                                              ↓
                          여기서 잡힌 것은 논쟁 없이 버그
                          여기서 안 잡히는 것(법 해석)만 에이전트로
```

불변식은 전부 "위반하면 법적으로 불가능한 결과이거나 스스로 모순"인 성질만 담는다.
반박할 여지가 없고, 위반 시 재현 방법(시나리오 id + 조건)이 자동으로 따라 나온다.

## 반복된 패턴 — 모델에 있는 사실을 엔진이 안 읽는다

같은 병이 **네 번** 났다.

1. 종부세가 `ResidenceSpell`을 안 읽어 거주 **여부**를 틀림 (2026-08-04)
2. 고쳐 놓고도 거주·보유 **기간**은 여전히 옵션만 봄 (SIM-01)
3. 양도세가 취득일을 안 읽어 보유기간을 None으로 둠 (SIM-06)
4. `Election`을 안 읽어 신청 진술을 무시 (SIM-04)

도메인 모델이 1급 엔티티로 두고 사용자에게 입력까지 받아 놓고, 엔진이 그걸 안 봤다.
**Streamlit 앱은 정상이었다** — 앱이 같은 사실을 별도 위젯으로 한 번 더 물었기 때문이다.
그래서 엔진을 라이브러리로 쓰는 모든 경로만 조용히 틀렸다.

대응: `engine/periods.py`를 만들어 "만 연수"의 정의를 **한 벌만** 뒀다.
정의가 흩어져 있으면 한 곳만 고치는 날이 반드시 온다.

## 골든 테스트가 왜 못 잡았나

정부 문답자료 골든값 11개(재산세 5 + 종부세 6)와 양도세 6값이 전부 통과하는 상태에서
위 여섯이 살아 있었다. 이유는 하나다.

> **테스트가 옵션을 손으로 먹여줬다.**

`JongbuseOptions(holding_years=10, residence_years=10)`처럼 아는 값을 넣어주는 테스트는
"사실에서 도출되는가"를 검증하지 못한다. 시뮬레이션은 사용자처럼 **사실만 주고**
나머지를 엔진에 맡겼기에 잡혔다.

이건 골든 테스트의 결함이 아니다. 골든은 *아는 것을 고정*하고, 시뮬레이션은
*모르는 것을 발견*한다. 둘은 대체재가 아니라 보완재다.

## 검사기가 틀린 경우 — 2건

불변식도 법을 알아야 한다. 두 번이나 **정상 동작을 위반으로 신고**했다.

**① 단조성을 종부세 단독에 걸었다.**
종부세법 §10은 `재산세 + 종부세 ≤ 전년총액 × 상한율`을 걸고, 초과분에서 깎이는 건
종부세뿐이다(재산세는 지방세법 §122 별도 상한 소관). 공시가격이 오르면 재산세가 올라
상한 여유분이 줄고, **종부세는 정상적으로 내려간다.** 농특세도 종부세액의 20%라 함께
줄어 총액이 경계에서 살짝 꺼진다.
→ 법이 보장하는 단조량은 `재산세 + 종부세 본세`뿐. 그것만 검사한다.

**② 세부담상한 검사가 법인 예외를 몰랐다.**
단일세율 법인은 상한 미적용(§10). 납세자 유형을 안 보고 검사해 정상 동작을 신고했다.

**③ "엔진이 알아서 유리한 쪽을 고른다"를 전제했다.**
§10의2는 **"신청한 경우"**에만 특례를 준다 — 9월 16~30일에 신청서를 내야 한다.
신청하지 않은 사람에게 특례 세액을 보여주면 실제로 낼 금액보다 적은 숫자를 알려주는 것이다.
→ 검사를 둘로 쪼갰다: ①진술한 신청이 반영되는가 ②신청이 유리하면 행동 가능한 안내가 뜨는가.

### SIM-07 — 세목 오염이 가장 위험하다

부산 1채 + 목포 1채(공시 3억)를 가진 사람이 **지방 저가주택 제외**로 1세대1주택자가
되어 양도차익 5.4억이 **전액 비과세**로 나왔다. 실측 세액 0원 → 1.7억원.

지방 저가주택 제외는 종부령 §4의2③이다. **소득세법에는 없다.** 양도세의 1세대1주택
주택수 특례는 소득세법 시행령 §155(일시적 2주택·상속·동거봉양·혼인 합가)가 따로 정하고
요건도 다르다. 남의 법으로 센 주택 수로 비과세를 내주면 **낼 세금보다 적은 금액**을
알려주는 것이고, 그대로 신고하면 과소신고 가산세가 붙는다.

과다 안내는 사용자가 놀라서 확인하지만, **과소 안내는 그대로 신고된다.**

조치: 양도세 전용 주택수 판정(`_transfer_house_count`)을 두고 **제외하지 않는다.**
대신 §155 특례에 해당할 만한 단서(최근 3년 내 취득·상속 취득·세대원 2인 이상)가 있으면
"해당할 수 있으니 확인이 필요합니다"를 actionable 대안으로 띄운다.

### SIM-08 — 윤년

민법 §160③: "최종의 월에 해당일이 없는 때에는 **그 월의 말일**로 기간이 만료한다."
국세기본법 §4가 기간 계산에 민법을 준용한다. 2024-02-29 취득분의 보유 2년은 평년인
2026년에 **2월 28일** 만료다. `(월, 일)` 단순 비교로는 하루가 밀려 보유 1년이 되고
2년 미만 단기세율 60%가 붙는다. 실측 840,000원 vs 8,400,000원.

같은 규칙이 나이에도 적용된다(2/29생의 만 70세 생일은 평년 2/28) — 60/65/70세
세액공제 구간이 윤년생만 밀리지 않도록 `Person.age_at`도 함께 고쳤다.

## 법령 대조 — 지적 3건 중 2건 생존

1차 출처(법제처 XML·개편안 PDF)만 쓰게 하고, 지적이 나오면 **반박자**를 붙여
"의심스러우면 기각"으로 판정하게 했다.

| 질문 | 판정 |
|---|---|
| 개편안 장특공제 3단계가 룰셋과 일치하는가 | **MATCHES** — 값 전부 원문과 일치 |
| §154① 비과세 요건이 빠짐없이 반영됐는가 | **MISMATCH · 생존** |
| 부부공동명의 특례의 세액공제 기준자 | **MISMATCH · 생존** (근거 조항 오기) |

**부부공동명의 건은 계산이 아니라 인용이 틀렸다.** 값(20/30/40%, 20/40/50%, 80%)은
전부 원문과 맞는데 근거 조항 번호가 어긋났다.

- `credit_holding`이 §9⑦을 가리켰다 → 보유기간 공제는 **§9⑧**이다.
  §9⑦은 상속·일시적2주택이 있을 때의 **연령별** 공제 특칙으로 전혀 다른 규범이다.
- `credit_rate_cap`이 §9⑧을 가리켰다 → 80% 한도는 **§9⑤ 후단**이다.
- 코드 주석의 `§9의4②`는 **존재하지 않는 조문**이었다.

근거를 보여주는 것이 이 서비스의 유일한 차별점이므로, 틀린 조항을 감사추적에 찍는 것은
계산 오류와 같은 급의 결함이다. 전부 고쳤다.

## 이번 회차에서 배운 것 — 검사기도 법을 알아야 한다

불변식이 **정상 동작을 위반으로 신고한 것이 3건**이다(단조성 대상, 법인 상한 예외,
특례 자동선택 전제). 실행 결과를 심판으로 삼는 방식의 강점은 여기서도 나온다 —
검사기가 틀렸다는 것을 **논쟁이 아니라 재현으로** 확인할 수 있었다.

에이전트 지적도 마찬가지다. 2회차에서 올라온 증상 20여 건 중 실제 버그는 4건이었고,
나머지는 SIM-06의 그림자이거나 우연한 고정점이거나 오독이었다. **읽어서 나온 의심은
대부분 틀린다**는 1회차의 교훈이 반복 확인됐다. 다만 남은 4건은 불변식으로는 영영
못 잡을 것들이었다 — 세목 경계, 민법 준용, 지역요건 문언, 조문 통산.

기계가 잡는 것과 사람(AI)이 잡는 것은 **다른 층위**다. 둘 다 필요하다.

## 남은 것

- `pt.03.house_count` 오피스텔 판정 불가 — 사용자에게 "주거용으로 실제 사용 중인가"를
  물으면 답을 줄 수 있다. 지금은 답을 못 받고 끝난다.
- 배우자를 납세의무자로 지정한 부부공동명의 특례에서 **본인 과세분 재귀속** 미구현.
  조용히 미신청으로 계산하지 않고 드러내도록만 해 뒀다.
- 세부담상한이 종부세를 0으로 눌러버리는 경우의 설명. 전년세액이 아주 작으면
  (신규 취득 등) 상한이 급증 방지 장치가 아니라 면세 장치가 된다.
- **소득세법 시행령 §155 주택수 특례 미구현** — 일시적 2주택·상속·동거봉양·혼인 합가.
  지금은 "해당할 수 있으니 확인 필요"로만 안내한다. 종부세용 판정을 재사용하면
  안 된다는 것이 SIM-07의 교훈이므로, 소득세법 전용 판정을 새로 짜야 한다.
- **§154⑧ 통산 미구현** — 멸실 주택의 취득일, 피상속인의 보유기간을 입력받지 않는다.
  통산 여지가 있으면 판정 불가로 드러내고 있으나, 흔한 상황이라 결국 물어봐야 한다.
- 룰셋에 **종부세법 §10의2·시행령 §5의2 블록이 없다.** 부부공동명의 특례의 핵심 규범
  (지분 합산, 재산세·상한의 전체지분 기준, 공제 기준자)이 코드 주석에만 있어
  개정이 와도 룰셋 diff로 검출되지 않는다.
