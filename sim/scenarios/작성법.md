# 시나리오 작성법

상황 한 건을 **사실만으로** 진술한다. 파일 하나에 `---`로 여러 건을 담을 수 있다.

## 절대 규칙 3가지

**① 판정 결과를 쓰지 않는다.**
`주택수: 2`, `1세대1주택: false`, `조정대상지역: true` 같은 필드는 **없다**.
셋 다 엔진이 사실에서 판정하는 값이다. 작성자가 답을 적어 넣으면 판정을 검증할 수 없다.
쓸 수 있는 것은 취득일·지분·법정동코드·거주 이력 같은 **관찰 가능한 사실**뿐이다.

**② `expectation`에 금액을 쓰지 않는다.**
AI가 지어낸 숫자를 정답표로 승격시키면 감사 전체가 무너진다.
방향과 성질만 쓴다 — "개편안이 현행보다 높다", "거주 요건을 못 채워 비과세가 안 된다".

**③ 모르는 필드를 만들어 쓰지 않는다.**
스키마에 없는 키는 **오류로 거부된다**(조용히 무시되지 않는다).
`acquired_on:`이 아니라 `acquired:`다. 오타는 파싱 단계에서 죽는다 — 그게 정상이다.

## 전체 필드

```yaml
id: r1-multi-01                  # 필수. 전역 유일
label: 다주택자 · 조정지역 2채 + 지방 1채   # 필수. 한 줄 요약
origin: multi-house-agent        # 어느 에이전트가 만들었나
intent: 무엇을 노렸나 — 어떤 로직을 깨려는 시나리오인지
expectation: 예상되는 성질 (숫자 금지)
tags: [다주택, 조정지역]

year: 2026                       # 필수. 기준연도
years: [2026, 2027, 2028, 2029]  # 선택. 타임라인. 비우면 year 한 해만
tracks: [current, reform]        # 선택. 기본값이 이것
growth: 0.0                      # 선택. 미래 공시가격 상승률
subject: p1                      # 누구의 세금인가 (종부세는 인별 과세)

prior_year_total_tax: 3_000_000  # 선택. 없으면 세부담상한이 판정 불가로 나온다
resides_in_main_house: true      # 선택. 보통 비우고 residences로 사실을 준다
joint_spouse_election: true      # 선택. 비우면 엔진이 신청/미신청을 비교한다

persons:
  - id: p1
    name: 김철수                  # 선택
    type: individual             # individual | corporation | corporation_progressive
    birth: 1956-03-02            # 연령 세액공제(60/65/70세) 판정
    household: h1                # 법인은 비운다
    spouse: p2
    is_resident: true            # 소득세법상 거주자

households:
  - id: h1
    members: [p1, p2]
    spouse_separately_registered: false
    independent_members: []      # 30세 미만이나 독립 생계

properties:
  - id: seoul1
    name: 강남 아파트             # 선택. 화면 표시용
    kind: apartment              # apartment|detached|multi_unit|officetel_residential
                                 # |land_comprehensive|land_separate|building_other
    dong: "1168010100"           # 필수. 법정동코드 숫자 10자리 (아래 목록)
    urban: true                  # 도시지역분 재산세 부과 여부
    area_m2: 84.9                # 선택
    prices: {2026: 1_500_000_000, 2027: 1_600_000_000}   # 연도별 공시가격
    company_housing: false
    unsold_new: false
    rental:                      # 등록임대주택이면
      type: purchased_long_term  # built_public_support|built_long_term
                                 # |purchased_public_support|purchased_long_term|short_term
      registered_on: 2020-01-15
      obligation_end: 2030-01-15
      rent_increase_within_cap: true

ownerships:
  - person: p1
    property: seoul1
    share: "1/2"                 # 분수 문자열. 0.33 같은 소수는 거부된다
    acquired: 2015-04-01
    cause: purchase              # purchase|inheritance|gift|new_build|reconstruction|other
    inherited:                   # cause: inheritance면 필수
      date: 2023-05-10
      share: "1/4"
      value: 300_000_000

residences:
  - person: p1
    property: seoul1
    start: 2015-04-01
    end: 2022-03-31              # 비우면 현재까지 거주 중
    imputed_reason: job_transfer # schooling|job_transfer|illness|school_violence
                                 # |overseas|elder_care|reconstruction|other

elections:
  - person: p1
    kind: joint_spouse_special   # joint_spouse_special|rental_exclusion|deferral
    year: 2026                   # 비우면 전 연도
    designated_taxpayer: p1
    auto_optimize: true

transfer:                        # 양도세. 선택
  property: seoul1
  person: p1
  date: 2027-06-15
  price: 2_000_000_000           # 양도가액
  acquisition_price: 900_000_000 # 매매계약서상 실지거래가액
  acquisition_date: 2015-04-01
  necessary_expense: 30_000_000
  share: 1
  holding_years: 12              # 선택. 비우면 취득일에서 도출
  residence_years: 7

burden_gift:                     # 부담부증여. 선택
  property: seoul1
  person: p1
  date: 2027-03-01
  appraised_value: 2_000_000_000 # 상증세법 §60~66 평가액
  gift_value: 2_000_000_000      # 증여가액
  debt_assumed: 800_000_000      # 수증자가 떠안는 채무
  acquisition_price: 900_000_000
  necessary_expense: 0
```

금액은 `1_500_000_000` 또는 `"15억 5,000만"` 둘 다 된다.
`"15억5000"`처럼 단위가 모호한 표기는 **거부된다**(5천원인지 5천만원인지 알 수 없다).

| `4113510100` | 성남시 분당구 | ✅ |

| `2647010100` | 부산 해운대구 | ❌ |

조정지역이었나"를 묻는 시나리오는 엔진이 판정 불가를 내는데, **그게 정상 동작이다**
(없는 이력을 지어내지 않는다). 그걸 버그로 신고하지 말 것.

## 좋은 시나리오의 조건

버그는 **경계와 모순**에 산다. 평범한 케이스 10건보다 아래 1건이 낫다.

- **경계 ±1원** — 기본공제 9억/12억/14억, 재산세 특례 9억, 상속 6억, 지방저가 3억
- **요건 딱 하루 차이** — 거주 2년 −1일, 보유 3년 −1일, 60세 생일 전날
- **모순된 사실** — 거주 이력이 두 줄로 겹침, 취득일이 상속개시일보다 이름
- **빈 값** — 취득일 없음, 공시가격 없음, 생년월일 없음, 전년 세액 없음
- **복합** — 상속 + 일시적2주택 + 임대등록이 한 세대에 동시에
- **구조** — 부부 각자 단독 1채씩 / 3인 공동명의 / 세대분리 / 법인과 개인 혼재
- **0과 극단** — 공시가격 0원, 지분 1/1000, 100억, 20채

## 실행

```
python -m sim.run --dir sim/scenarios/gen/r1
```

명세 오류는 **엔진 버그가 아니라 시나리오 오류**로 따로 보고된다. 그건 고쳐야 한다.
