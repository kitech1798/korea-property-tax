## 무엇이 다른가

시중 계산기의 실패는 버그가 아니라 **구조**였다. 그 구조를 설계로 배제했다.

| 흔한 실패 | 이 엔진 |
|---|---|
| 데이터 모델에 "사람"이 없어 *"부부 각자 1채씩"*을 **표현조차 못 함** | `Person`/`Household`/`Property`/`Ownership` 4엔티티. 지분은 `Fraction` |
| 주택 수를 **판정하지 않고** 사용자에게 물음 (사용자는 그걸 몰라서 왔다) | 사실만 받고 상속·일시적2주택·합산배제·지방저가를 **엔진이 판정** |
| 조정대상지역을 `주소.startsWith('서울')`로 **추측** | 법정동코드로만 판정. 모르면 `UNKNOWN`으로 흘리고 양쪽을 보여줌 |

| **면책 문구가 기능을 대체** | 적용되지 않은 특례를 *왜* 안 됐는지와 함께 나열 |

### 재현되지 않은 것 — 숨기지 않는다

문답자료 p.47 별첨 ➂(3주택)의 **재산세**는 엔진과 다르다.
정부 예시는 3채를 합산해 한 물건처럼 계산했고, 4개 가액 구간 전부가 그 방식으로 정확히 재현된다.
그러나 재산세는 지방세법상 **물건별 과세**이고 누진세율도 물건별로 적용된다.

| 공시 합계 | 정부 예시(합산) | 법대로(물건별) |
|---|---|---|
| 15억 (5억 × 3채) | 482.4만원 | **331.2만원** |

엔진은 법대로 간다. 차이 자체를 `tests/test_property_tax.py`에 테스트로 고정해,
나중에 누가 "정부 숫자에 맞추자"며 조용히 바꾸는 일을 막는다.

## 조사에서 확인한 것들

세법 해설이 흔히 틀리는 지점들. 전부 조문 원문으로 확인했다.

- **주택 재산세의 세부담상한(105/110/130%)은 폐지됐다.** 지방세법 §122 단서:
  "다만, 주택의 경우에는 적용하지 아니한다." 2023년부터 **과세표준상한제**(§110③)로 대체됐다.
- **1세대1주택 재산세 세율 특례는 시가표준액 9억원 이하 한정**(§111의2① 괄호).
  공시 30억 1주택자는 특례세율이 아니라 표준세율을 쓴다.
- **1주택 재산세 공정시장가액비율 43/44/45%는 2026년도 한정**(시행령 §109①2 단서).
  2027년 이후는 시행령이 다시 정하지 않으면 60%로 돌아간다.
- **종부세 재산세 공제(시행령 §4의3①)의 분자는 한계세율로 계산해야 한다.**
  누진 전체로 적용하면 정부 문답자료 값이 하나도 맞지 않는다. 정부가 계산 과정을
  공개하지 않은 부분이라 확실성을 `assumed`로 표시한다.
- **2차 출처는 쓰지 않는다.** 한 세무 전문지는 장기보유특별공제 개편을
  "거주 연8% 최대80%" 한 단계로 요약했지만, 원문은
  '27 현행유지 → '28 거주6%+보유2% → '29~ 거주8%의 **3단계**다.

### 공시가격 자동조회 — 실측 검증 완료 (2026-08-04)

압구정 한양1차(강남구 압구정동 490, 936호) 실호출 결과.

```
전유부 936호 · 주택가격 17,784건(2008~2026 각 936건)
mgmBldrgstPk 조인 채움률 100.0% (936/936호)
2026년 공시가격 실재 — 예: 7동 1201호(78.05㎡) 34.76억
```

⚠️ **실호출로 잡은 함정 두 가지** (둘 다 조용히 틀리는 종류다)

1. **기준일은 `stdDay`다.** `crtnDay`는 대장 생성일이라 한 단지의 모든 행이 같은 값
   (예: 20220813)을 갖는다. 그걸 기준일로 쓰면 연도 필터가 무너져 2026년 조회가 0건이 된다.
2. **반드시 전 페이지를 훑어야 한다.** 전유공용면적은 호당 약 6행, 주택가격은 호당 19행이
   쌓여서 각 1페이지가 **서로 다른 호 집합**을 덮는다. 1페이지만 받으면 조인 교집합이 비어
   채움률이 **0%**가 나온다. `call_all()`이 이걸 처리한다.

두 함정 모두 `pytest -m live`의 회귀 테스트로 고정했다.

**아직 남은 수동 검증**: 이 값이 공동주택공시가격과 **동일한지**는 알리미와 눈으로 대조해야
확정된다(알리미는 API가 없다). 참고로 같은 단지 78.05㎡ 실거래 47.5억 대비 공시 34.76억으로
현실화율 73%인데, 공동주택 평균 69%와 정합적이다 — 일치의 증거는 아니고 모순이 없다는 정도다.
그래서 화면의 '수정' 경로는 항상 열어 둔다.

## 설계 원칙

시중 계산기가 무너진 자리를 **설계로** 막는다.
([propertytax.co.kr](https://propertytax.co.kr/)의 프론트엔드 코드를 분석한 결과)

| 경쟁자 실패 | 이 엔진의 대응 |
|---|---|
| `properties[]`에 소유자 필드가 없어 "부부 각자 1채씩"을 **표현조차 못 함** | Person / Household / Property / **Ownership**을 각각 1급 엔티티로 |
| 주택 수 = 사용자가 담은 개수 | 사실만 받고 `determination.py`가 **판정**한다 |
| 조정대상지역 = `주소.startswith('서울')` | 법정동코드만 받고, 고시 이력 테이블 조회로만 판정 |
| 서버가 준 숫자를 렌더링만 (감사 불가) | 모든 값이 `Value`(출처+확실성), 모든 단계가 `TraceNode`(산식+대입값+조문) |
| "유의사항: ○○ 미반영" 정적 면책 | `alternatives_not_taken` — 엔진이 판정하고 **왜 안 됐는지**를 남긴다 |
| 지분을 1~99 정수 퍼센트로 | `Fraction` — 3인 1/3 공동명의 합이 정확히 1 |
| 특례를 "관할 세무서 문의"로 회피 | 상속·일시적2주택·지방저가·합산배제를 **엔진이 판정**하고, 못 하면 사유를 남긴다 |

### 주택 수 제외 ≠ 합산배제

섞으면 세액이 통째로 틀리는 구분이다.

| | 근거 | 효과 |
|---|---|---|
| **주택 수 제외** | 종부세법 §8④ | 1세대1주택자 판정에서만 뺀다. **과세표준에는 그대로 합산된다** |
| **합산배제** | 종부세법 §8② | 과세표준에서 빠진다. 그 주택엔 종부세가 안 붙는다 |

그리고 **재산세와 종부세는 주택 수 판정 기준이 다르다.** 지방세법 시행령 §110의2의
제외 목록에는 등록임대주택이 없어서, 같은 사람이 종부세로는 1주택이고 재산세로는 2주택일 수 있다.
두 세목의 판정을 한 함수로 뭉뚱그리면 여기서 조용히 틀린다.

### 확실성 3축

모든 값이 확실성을 들고 다니고, 계산이 진행될수록 가장 약한 고리로 자동 강등된다.

| 축 | 값 |
|---|---|
| A 법적 확정도 | 현행법 / 시행예정 / **국회 미통과** / **시행령 미정** / 가정 |
| B 입력 확실도 | 고지서 확인 / 공적 조회 / 사용자 입력 / 추정치 / 미상 |
| C 판정 확실도 | 확정 / 가정 판정 / **판단 필요** |

개편안은 아직 국회를 통과하지 않았다. 그래서 "얼마 나오나요"의 정답은 하나가 아니라
둘(`current` / `reform`)이고, 둘을 나란히 보여주지 않는 것 자체가 오류로 본다.

## 배포

### 먼저 — 훅을 연결한다 (한 번만)

```bash
git config core.hooksPath hooks
```

`hooks/pre-push`가 **푸시 직전에 이력 전체를 비밀 스캔**한다. 이게 없으면
`tools/deploy.ps1`의 게이트를 `git push` 한 줄로 우회할 수 있다 —
이 저장소는 실제로 그렇게 자택 IP를 공개한 적이 있다(2026-08-13, 이력 세탁 완료).

훅은 **되돌릴 수 없는 것 하나**(비밀 유출)만 막는다. 테스트·룰셋·시뮬레이션까지
걸면 푸시가 1분 넘게 걸려 사람이 `--no-verify`를 쓰게 되고, 그러면 훅이 없는 것과 같다.
나머지 게이트는 `tools/deploy.ps1`이 맡는다.

탐지 문자열은 `tools/.secret-needles.txt`(gitignore 대상)에 한 줄에 하나씩 적는다.
**파일이 없으면 푸시를 멈춘다** — 스캔을 조용히 건너뛰는 것이 가장 나쁜 실패다.

### 🔴 실측 — 해외 호스팅에서는 주소 검색이 안 된다 (2026-08-13)

위 경고를 **확인하지 않고 배포했다가 실제로 걸렸다.**

| 환경 | `business.juso.go.kr` |
|---|---|
| 로컬 (한국 회선) | 0.3초 · HTTP 200 · 정상 |
| Streamlit Cloud (미국 AWS) | **20초 타임아웃** |

주소정보 누리집이 해외 IP에 응답하지 않는다. 인증키·앱 문제가 아니다.
`apis.data.go.kr`(건축HUB)는 같은 서버에서 응답하므로 **호스트마다 다르다.**

### ✅ 대응 — 법정동 + 지번으로 사슬을 잇는다 (2026-08-13 구현)

자동조회에 필요한 두 값 중 **법정동코드는 도달 가능한 호스트에서 받을 수 있고**
(`apis.data.go.kr/1741000` 행정표준코드), **지번은 사용자가 안다**(등기부·계약서).

```
juso 있음   "북일로 70"        → 법정동코드 + 지번        (한 줄)
juso 없음   "신부동" + "978"   → 법정동코드(코드API) + 지번(사용자)
                                 → 동·호·공시가격은 그대로 자동
```

juso가 `NETWORK`로 실패하면 화면이 자동으로 이 입구를 연다. 편의 하나(주소 한 줄)를
잃되 **사슬 전체를 잃지 않는다.** 법정동코드만 채워도 조정대상지역 판정이 살아난다.

⚠️ **도로명은 못 찾는다** — 이 API는 법정동명만 안다("북일로" → 0건). 화면이 먼저 말한다.
⚠️ data.go.kr 활용신청의 허용 IP가 `*.*.*.*`가 아니면 배포 서버에서 **403**이다.
   403은 타임아웃과 원인이 다르므로 화면이 구분해 알린다.

### ✅ 도로명 검색 되살리기 — 서울 리전 중계 (선택)

앱을 국내로 옮기는 대신 **중계만 서울에 둔다.** `api/juso.mjs` + `vercel.json`
(`"regions": ["icn1"]`)이 그것이다. 붙이면 도로명 검색이 그대로 살아난다.

**승인키는 중계에만 둔다.** 앱은 검색어만 보내고 키는 중계가 붙인다 — 키가 두 곳에
있으면 두 곳에서 샌다. 앱 쪽 `JUSO_CONFM_KEY`는 없어도 된다.

**설정 (한 번)**

1. Vercel에서 이 저장소로 프로젝트를 만든다. `.vercelignore`가 앱 본체를 가리므로
   중계 함수 하나만 올라간다(⚠️ `requirements.txt`가 보이면 Vercel이 파이썬 프로젝트로
   잡고 streamlit까지 설치하려 든다).
2. Vercel → Settings → Environment Variables

   | 이름 | 값 |
   |---|---|
   | `JUSO_CONFM_KEY` | juso 승인키 |
   | `PROXY_TOKEN` | 아무 긴 무작위 문자열 |

3. Streamlit Cloud → App settings → Secrets

   ```toml
   JUSO_PROXY_URL = "https://<프로젝트>.vercel.app/api/juso"
   JUSO_PROXY_TOKEN = "2번에서 정한 그 값"
   ```

**막아 둔 것**
- `PROXY_TOKEN`이 없으면 중계가 **기동을 거부한다.** 열린 중계를 두지 않는다.
- 경로 화이트리스트 — 앱은 `path=addrLinkApi.do`처럼 **이름만** 보낸다. 전체 URL을
  받으면 아무 데나 요청을 보내주는 도구가 된다(SSRF).
- 토큰은 **헤더**로 보낸다. 쿼리는 로그·리퍼러에 남는다.
- 파라미터 화이트리스트 — 승인키·토큰이 상류로 새지 않게 넘길 것만 정해 뒀다.

⚠️ juso 승인키의 등록 URL이 Streamlit 주소로 돼 있다. 중계에서 막히면
`business.juso.go.kr` 신청 내역에 Vercel 주소를 추가한다.

### 더 나아가려면

**국내 IP 호스팅** — 중계도 필요 없어진다. 해외 PaaS는 전부 막힌다.

⚠️ **juso 승인키는 URL(또는 IP) 기준으로 부여된다.** 아웃바운드 IP가 고정이 아니므로
서버사이드 호출에서 검증이 어떻게 걸리는지 **배포 후 실제로 확인해야 한다.**
오프라인 테스트는 이 층을 한 번도 보지 않는다(`pytest -m live`가 그 층이고 기본 제외다).

배포에서 제외해도 되는 것: `corpus/`(389쪽 원문 텍스트), `세제개편안_8.3/`(PDF), `tools/`.
런타임에 필요한 것은 `rulesets/`뿐이다.

- **나머지 특례** — 소형 신축주택, 준공 후 미분양, 인구감소지역 주택(종부령 §4의3③3바)의
  주택 수 제외. 상속·일시적2주택·지방저가·합산배제는 구현 완료.
- **개편안 다주택 기본공제 신공식** — `4억 + 5억 × (거주주택가액 ÷ 합계액)`을 구현했고
  문답자료 p.40 수치와 일치하나, 거주주택이 2채인 경우·지분 반영 시점 등
  시행령 미정 영역이 남아 `decree_pending`이다.
- **Phase 5 Streamlit UI** — 미착수. 엔진·판정·전략·입력 계층은 준비됐다.
- **양도세의 남은 부분** — 단기 보유 중과세율(1년 미만 70% / 2년 미만 60%), 부담부증여,
  상생임대주택 거주요건 면제, 고령 1주택자 한시 감면(조특법 §71의3 신설안).
  해당 상황이면 `alternatives_not_taken`으로 **안내**는 한다.
- **취득세·상속증여세** — 범위 밖. 취득세는 지방세라 이번 개편안 대상이 아니다.
- **2025-10-16 이전 규제지역 이력** — 미수집. 그 이전 취득 시점 판정은 하지 않는다.
